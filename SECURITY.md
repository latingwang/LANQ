# Security Policy

This policy covers security issues related to the `latingwang/LANQ` repository.

## Reporting a vulnerability

Please use [GitHub private vulnerability reporting](https://github.com/latingwang/LANQ/security/advisories): sign in to GitHub and select **Report a vulnerability**, if available. This channel can accept reports only when a repository administrator has enabled private vulnerability reporting.

Do not disclose vulnerability details in public issues, pull requests, discussions, or comments.

If the private reporting option is unavailable, open a public issue only to ask maintainers to enable private vulnerability reporting or provide a private reporting channel. Include no vulnerability details, proof-of-concept code, or sensitive information in that request.

## What to include in a private report

- Affected files or components, and the commit or tag if known.
- Relevant environment and steps to reproduce.
- A minimal proof of concept, if available.
- Expected behavior, observed behavior, and potential security impact.
- Suggested mitigation or fix, if available.

Remove credentials and personal data from examples and logs; use test data where possible.

## Follow-up and disclosure

Keep technical details and follow-up in the private report. Use it to coordinate validation, any remediation, and public disclosure with the maintainers before publishing vulnerability details.

This policy does not promise response, remediation, or disclosure deadlines.
